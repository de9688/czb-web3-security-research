# Research Methodology

CZB Security Lab uses an evidence-first workflow for public Web3 security research.

## 1. Intake

- Define the incident or risk question.
- Record affected chains, contract addresses, transaction hashes, timestamps, and public references.
- Separate verified facts from unverified claims.

## 2. Evidence Handling

- Preserve original transaction links and explorer snapshots.
- Redact victim-identifying data unless explicit public consent exists.
- Keep notes reproducible without requiring private credentials or secret material.

## 3. Analysis

- Map wallet, contract, and approval relationships.
- Identify attacker-controlled addresses only when evidence supports the label.
- Prefer public chain data, official notices, and direct project documentation.

## 4. Review

- Check for overclaims, missing citations, and unsafe operational detail.
- Remove instructions that would help unauthorized access or active abuse.
- Link back to canonical CZB pages for entity consistency.

## 5. Publication

- Publish concise findings, practical prevention notes, and limitations.
- Include dates, affected networks, and source links.
- Update the note when material facts change.
